# 과제 요구사항 전체 대응표

## 2. 최종 결과물

| 제출물 | 준비 위치 | 마지막에 사용자가 할 일 |
| --- | --- | --- |
| Vercel 웹서비스 URL | 전체 코드와 `vercel.json` | Vercel 계정으로 배포하고 실제 URL 기록 |
| GitHub 저장소 | 프로젝트 전체 | 새 저장소에 push하고 공개 테스트 가능 상태 확인 |
| README.md | `README.md` | 실제 GitHub/Vercel URL로 자리표시자 교체 |
| 서비스 기획서 | `docs/SERVICE_PLAN.md` | 이름·목표가 본인 의도와 맞는지 최종 확인 |
| 증빙 자료 | `evidence/README.md`, 단계별 가이드 10단계 | 실제 배포 화면과 AI 코딩 과정을 캡처 |

## 4. 기능 요구사항

| 번호 | 요구 의미 | 구현 | 검사 |
| --- | --- | --- | --- |
| 1 | 무엇을 누구에게 왜 만들지 먼저 정하기 | 서비스 기획서 | 목적·타깃·AI 입출력 읽기 |
| 2 | 폴더와 Git 이력으로 작업을 되돌릴 수 있게 하기 | 화면/API/문서 분리 | `git status`, GitHub 파일 확인 |
| 3 | 프레임워크 없이 기본 웹 기술 사용 | HTML/CSS/JS | `index.html`, `css/`, `js/` |
| 4 | 휴대폰과 PC 모두 정상 표시 | 3개 반응형 구간 | 1440px와 390px 직접 캡처 |
| 5 | AI 입력·출력과 실패 메시지 제공 | 입력 폼, 결과 렌더링, 오류 상자 | 정상·빈 입력·오류 테스트 |
| 6 | Python이 비밀 키로 AI를 호출 | `api/`와 `lib/backend.py` | `/api/health`, 실제 생성 |
| 7 | GitHub 변경이 Vercel 재배포로 이어짐 | 배포 구조와 가이드 | 수정 커밋 후 배포 상태 확인 |
| 8 | 다른 사람이 다시 만들 수 있게 문서·증빙 | README와 docs/evidence | 제출 5종 체크 |

## 5. 보너스 과제

| 보너스 | 구현 | 개선 효과 | 확인 방법 |
| --- | --- | --- | --- |
| 운영 자동화/저장 | 생성 즉시 최근 여행 5개 localStorage 저장, 후보 풀 재사용 | 새로고침 복구, 개별 재추천 비용·대기 감소 | 생성 → 새로고침 → 최근 여행 열기 |
| UX/측정 | 다크 모드, 로딩, 미세 상호작용, 모션 감소, 로컬 지표 | 읽기 편함, 처리 중 상태 이해, 효과 수치 확인 | 두 테마·390px·응답시간 캡처 |

## 6. 개발 환경

| 제한 | 적용 |
| --- | --- |
| 순수 HTML/CSS/JavaScript | React·Vue 없이 구현 |
| Vercel Serverless Functions Python | `BaseHTTPRequestHandler`를 상속한 `handler` 클래스 |
| `api/` 폴더 | 각 Python 파일이 같은 이름의 `/api/...` 주소가 됨 |
| AI 기능 최소 1개 | AI 지역 후보와 AI 여행 계획, 두 기능 포함 |

## 7. 제약 사항

| 위험 | 방어 방법 |
| --- | --- |
| 키 노출 | `.env` Git 제외, 서버 환경 변수만 사용, 오류에 원문 미출력 |
| 과금·쿼터 | 저비용 모델 기본값, 출력 제한, 개별 재추천은 API 재호출 없음 |
| API 실패 | 상태별 한국어 오류와 브라우저 26초 타임아웃 |
| 키 유출 | 즉시 폐기·재발급, Git 기록 정리 안내 |
| 필수 제출 누락 | 제출 템플릿과 증빙 10단계 |
| 예제 복제 | 독자적인 동네 여행 구조·문구·디자인 |
| URL 재현 실패 | 시크릿 창/다른 휴대폰 최종 테스트 |
